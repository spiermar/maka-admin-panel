# Internationalization (i18n) Design

## Overview

Add internationalization support to the Financial Ledger application using next-intl, enabling translation of all user-facing UI strings with Brazilian Portuguese (pt-BR) as the first translation.

## Technology Choice

- **Library**: next-intl (v4.x)
- **Rationale**: Best integration with Next.js App Router, native support for server components, middleware, interpolation, and pluralization

## URL Strategy

- **Query Parameter**: `?lang=pt-BR`
- **Fallback**: English (`en`) as default
- **Persistence**: Store preference in cookie

## Architecture

```
lib/i18n/
├── request.ts      # Request config for next-intl
└── config.ts       # Supported locales and defaults

messages/
├── en.json         # English (default)
└── pt-BR.json      # Brazilian Portuguese
```

### Middleware Flow

1. Check for `lang` query parameter
2. If present, set cookie and continue
3. If not present, check cookie for saved preference
4. Default to `en` if neither exists

## Translation Scope

All user-facing strings:

| Page/Component | Translated Elements |
|---------------|---------------------|
| Login | Labels, buttons, error messages, page titles |
| Dashboard | Page title, chart titles, loading states |
| Accounts | Page title, empty state, account cards |
| Transactions | Table headers, form labels, dialog text, delete confirmations |
| Expense Reports | Button labels, status text, form fields, empty states |
| Settings | Category/account manager dialogs, delete confirmations |
| Common | Error messages, success messages, confirmations |

## Implementation Steps

1. Install next-intl
2. Configure middleware for language detection
3. Set up request config
4. Create translation JSON files
5. Update root layout with provider
6. Replace hardcoded strings with translations
7. Test language switching

## Testing

- Unit tests for translation keys coverage
- E2E tests for language switching functionality
- Verify all user-facing strings are translated
